# Rawhide — What's New (Nightlies)

These notes feed the in-app "Update Available" dialog for Rawhide / cutting-edge builds.

## Recent improvements (unreleased — ships in the next build)

- 🎯 **Stuck quest steps retire themselves** — if the story has clearly moved past a quest step (the completion check keeps saying "not done" turn after turn while the plot sails on), that step no longer blocks the quest line forever. After 8 straight misses it's treated as overtaken by events, the step is checked off, and the character is free to move to the next step — or dream up a new goal if that quest is finished.

- 🎯 **Quest checking went from minutes to seconds on local models** — after each reply, the app asks the model whether your character's quest steps were completed. It was asking about EACH quest in a separate full request (re-reading the same conversation every time), and on "thinking" models it let the model silently reason at length before answering a simple yes/no. All quests are now checked in one single request, with thinking switched off for it — on a big local thinking model that's the difference between a 4-minute "Objectives" spinner and a few seconds, with the same verdicts.

- 🔄 **Switching backends now refreshes the model list by itself** — going from oMLX to a remote API (or back) used to leave the previous provider's models sitting in the chat-side model dropdown with no way to refresh them. The app now pings the newly selected provider for its model list the moment you switch, the dropdown works for remote APIs too (it was oMLX-only), and — a quiet bug this uncovered — the per-chat model choice you make in Chat Settings now genuinely drives generation (it was being saved but silently ignored; every reply used the global model).

- 📊 **The prompt-reading progress bar stops ping-ponging** — on oMLX (and any backend with live status) the bar could jump forward, snap backwards, and jump forward again every second — it was second-guessing itself between the server's real updates, and sometimes flickering between two different requests' progress. The bar now only ever moves forward (it briefly holds still when it got ahead of reality, then continues), it stays locked onto *your* request instead of hopping to a background task's, and it glides smoothly instead of stepping. Same fix on the web app automatically.

- ⚡ **Local backends can finally reuse their homework between replies** — the last two "cache busters" in the prompt are gone: the character's Journal memories (which re-sort with their mood every single turn) and the "story so far" recap used to sit *above* the chat transcript, so any change to them forced your backend to re-read the entire conversation from scratch before every reply. They now ride below the transcript (where this morning's memory fix already lives), so KoboldCpp, oMLX, and LM Studio can serve each reply from their prompt cache instead of re-reading thousands of tokens — on big local models that's the difference between waiting ~45 seconds and ~1 second before the reply starts in a long chat. What the character remembers and feels is unchanged; only where it sits in the prompt moved.
- ⚡ **Long chats got dramatically faster on local models** — once a conversation fills the model's memory window, the app used to make your GPU re-read the entire chat before every single reply. Two fixes measured on real hardware: old messages now scroll out in small batches instead of one at a time, and retrieved memories moved below the transcript so they stop forcing a full re-read. On a Gemma 31B, a typical reply's "reading" phase went from ~15 seconds to about 1 second. (Biggest win on Gemma-family models; every local model benefits.)
- 🎭 **Characters stop reciting their stats** — the realism engine no longer feeds the AI a wall of raw numbers ("hunger: 41/100…") that some models would blurt out mid-scene ("My hunger at 41 causes my stomach to grumble"). The AI now gets everything as natural language — "her stomach keeps growling; she hasn't eaten since morning" — so those immersion-breaking stat readouts are gone at the source. The same rewrite cut the behind-the-scenes state notes to a fraction of their old size, which means more room for your actual conversation and your character's real personality in every reply.
- 🤫 **Quiet moments stay quiet** — when nothing is pressing (needs fine, mood settled), the engine now whispers a couple of lines to the AI instead of shouting a full status report every single turn. Only what actually matters right now gets mentioned, so it colors the scene naturally instead of dominating it.
- 👥 **Group members can genuinely dislike you now** — a long-standing gap meant characters in group chats could only express the *warm* end of a relationship; hostility quietly flattened to "neutral". Groups now use the exact same full emotional range as 1:1 chats, from devoted to openly antagonistic.
- 🛑 **Your custom stop strings finally work** — user-added stop sequences (and character-name stops) were silently never being sent to the model; a hidden safety net trimmed the visible text so nobody noticed, but the model kept generating wasted words past the end. All your stops now reach the model properly, so replies end crisply where they should.
- 🧠 **Long-chat memory no longer eats the character card** — in very long chats, retrieved memories could quietly push the prompt over the model's limit, and the first thing to get cut was the character's own personality. Memory now always fits inside the budget, so your character stays themselves no matter how long the story runs.
- ⚠️ **The Journal switch now warns you** — turning the Journal off also pauses long-term memory and the "Where we are" recap; the toggle now says so (desktop and web) instead of letting you switch off your character's memory by accident.
- ⚡ **Prefill batch sizes above 4096 now actually work** — picking 8192 in Settings → Backend used to silently break the local backend launch (KoboldCpp's launcher rejects values that high on the command line, even though its engine handles them fine). The app now slips large values past the launcher through a config file, so big-memory Macs can use the full 8192 batch for faster prompt loading.
- 🔍 **The generation status bar tells the truth now** — instead of a vague "Processing prompt" that could sit for minutes, the app now reads the local backend's own progress and shows exactly what's happening: "Reading prompt — 1.8K / 4.2K tokens (43%)" with a real progress bar, "Waiting — journal pass is using the model", or "an earlier call is finishing". The web app shows the same live status in the chat, so the wait before a reply is never a black box again.
- ⚡ **Live progress now works on oMLX and LM Studio too** — the truthful status bar (live token counts while your prompt is read, honest "waiting" reasons) no longer needs the built-in KoboldCpp backend: oMLX users get it through the server's own stats (including "waiting behind another request"), and LM Studio users get it automatically when LM Studio's command-line helper is installed. Plain cloud APIs still show the simple timer — they don't share progress with anyone.
